# ESP32 Climate Camera v2.1.0 — психрометрическая пара DS18B20

Исходная база: https://github.com/vahmurka1975/ESP32-2-4TFT-WiFI-Climate-Camera (ветка main, v2.0.0).
Эта адаптация не является опубликованным релизом автора репозитория. Датчик SHT30/31 заменён двумя DS18B20.
Сохранены ILI9341 2.4 дюйма 240×320, Wi-Fi STA+AP, Web UI, REST API, mDNS, Web OTA и исходные GPIO остальных узлов.
Это НЕ вариант ST7789 240×240 и НЕ вариант HTU21D.

## Подключение пары

Только трёхпрводное питание. Каждый DS18B20 получает 3.3 V и общий GND.
Сухой зонд: DQ к GPIO21, отдельный резистор 4.7 кОм между DQ и 3.3 V.
Влажный зонд: DQ к GPIO22, отдельный резистор 4.7 кОм между DQ и 3.3 V.
На каждой шине должен быть ровно один DS18B20 (семейство ROM 0x28). Другие устройства не подключать.
НЕ соединяйте GPIO21 и GPIO22 вместе: это две отдельные шины 1-Wire, а не I2C.
Паразитное питание отвергается драйвером. Не подключайте подтяжки DQ к 5 V.
Роль определяется GPIO, а не порядком поиска ROM; физическая перестановка двух зондов не обнаруживается автоматически.
ROM-адреса выводятся при инициализации в Serial Monitor 115200.

На влажном зонде нужен чистый постоянно смоченный хлопковый фитиль с дистиллированной водой.
Сухой зонд нельзя смачивать. Оба зонда располагаются в одном потоке, вдали от стенок и прямого пара.
Для выбранного коэффициента нужен непрерывный равномерный обдув порядка 2–4 м/с.
Аспиратор должен иметь независимое постоянное питание: управляемый камерой вентилятор при аварии отключается.
Обороты вентилятора сами по себе не определяют скорость воздуха у фитиля.
После установки и смачивания дождитесь температурного равновесия. Толстые герметичные металлические зонды
имеют большую инерцию: для них может потребоваться увеличение SENSOR_PERIOD_MS/SENSOR_STALE_MS и проверка динамики.

## Принцип расчёта и ограничения

Температура камеры = температура сухого термометра.
RH = 100 * [e_s(Twet) - A0*(1 + 0.00115*Twet)*P*(Tdry - Twet)] / e_s(Tdry).
e_s(T) = 6.1121 * exp((18.678 - T/234.5) * T/(257.14 + T)), hPa (Buck, над жидкой водой).
P — местное АБСОЛЮТНОЕ давление, не приведённое к уровню моря. По умолчанию 1013.25 hPa.
A0 = 0.00066 1/°C — начальное значение для аспирируемого психрометра, а не универсальная калибровка.
В Config.h можно задать PSYCH_PRESSURE_HPA, PSYCH_COEFFICIENT, PSYCH_DRY_OFFSET_C,
PSYCH_WET_OFFSET_C и PSYCH_PAIR_TOLERANCE_C; после изменения нужна пересборка.
Никакого датчика давления в этой версии нет; высота и погода влияют на результат.
Диапазон: сухой 2…50 °C, влажный 0.5…50 °C. Ниже 0.5 °C на влажном зонде управление запрещается;
ледяной психрометр и отрицательные температуры не поддерживаются.
Если Twet выше Tdry более чем на 0.5 °C, расчёт отвергается; внутри допуска используется RH=100%.
Физически недопустимое/неположительное давление водяного пара считается ошибкой, а не подменяется 0%.

Разрешение DS18B20: 12 bit (0.0625 °C); точность реального датчика хуже разрешения.
Пару необходимо проверить совместно сухой при одинаковой температуре и откалибровать разность показаний.
Ошибки пары в доли градуса особенно заметны при высокой RH. Проверяйте RH независимым эталоном.
ВАЖНО: высохший фитиль может дать Twet≈Tdry и ложные 100% RH. Только по двум температурам
прошивка не может надёжно обнаружить отсутствие воды, неверный обдув или перестановку зондов.
Для автономной эксплуатации нужны контроль уровня воды/обдува и независимые аппаратные ограничители.

## Управление и защиты

Компрессор: 5 минут паузы при старте и после выключения; минимум включения 2 минуты,
максимум непрерывного включения 40 минут (как в исходной версии).
Увлажнитель: до 20 секунд работы, затем минимум 120 секунд паузы; циклы до достижения целевой RH.
Гистерезисы температуры и влажности сохранены. IN3/GPIO14 — резерв, постоянно LOW; осушителя нет.
Остальные реле активны HIGH: IN1/GPIO15 вентилятор, IN2/GPIO17 увлажнитель, IN4/GPIO26 холодильник.
При обнаруженной ошибке любого DS18B20 (обрыв, CRC, питание, расчёт) или устаревании >7 секунд
все управляющие реле отключаются. Ошибка выявляется при очередном опросе, не мгновенно при физическом обрыве.
Повторное обнаружение пары выполняется автоматически. Повторный запуск компрессора снова ждёт 5 минут.
Ожидание 800 ms конверсии неблокирующее. Кнопка дисплея также переведена на неблокирующий антидребезг.
Период опроса 2 секунды. Защитная переинициализация TFT не добавлялась.
При Web OTA выходы отключаются до начала записи Flash и остаются отключёнными до перезапуска.
После неудачной OTA климатический цикл возобновляется, с обычной защитой компрессора.

## Arduino IDE 1.8.19 / 2.x

Установите ESP32 core 2.0.17. Вариант core 3.x не поддерживается этим исходным API LEDC/WDT.
Из папки libraries скопируйте OneWire и TFT_eSPI в каталог библиотек Arduino, не создавая двойного вложения.
В комплектном TFT_eSPI уже применён нужный User_Setup.h. Если используете установленную TFT_eSPI,
замените её User_Setup.h файлом TFT_eSPI_setup/User_Setup.h из архива.
Не держите две копии библиотеки с одинаковым именем в разных пользовательских каталогах.
Откройте ClimateCamera_2_1_0_Psychrometer/ClimateCamera_2_1_0_Psychrometer.ino.
Плата ESP32 Dev Module; Flash 4MB; Partition Scheme Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS);
скорость Upload 115200 или 921600; Monitor 115200. Нажмите Загрузить.
Если изменена конфигурация GPIO или релейного модуля, пересоберите, не используйте комплектный бинарник.

## Готовые бинарники

binaries/ClimateCamera_2.1.0_DS18B20.full.bin — полный образ для начальной прошивки через USB, offset 0x0.
Пример: python -m esptool --chip esp32 --port COM5 --baud 460800 write_flash 0x0 ClimateCamera_2.1.0_DS18B20.full.bin
COM5 замените на свой порт; на Linux, например, /dev/ttyUSB0. Полный образ НЕ загружать через OTA.
Он содержит bootloader, таблицу разделов, boot_app0 и приложение. Существующая NVS не стирается автоматически.
binaries/ClimateCamera_2.1.0_DS18B20.app.bin — только приложение, для страницы http://<IP>/update.
При ручной раздельной первичной записи: bootloader.bin 0x1000, partitions.bin 0x8000,
boot_app0.bin 0xe000, .app.bin 0x10000. Объединённый .full.bin записывается только с 0x0.
Не обновляйте загрузчик/таблицу разделов через Web OTA. Если текущий layout несовместим,
используйте полную прошивку через USB. Перед OTA убедитесь, что размер .app.bin помещается в текущий OTA-слот.
Бинарники предназначены для классического ESP32 WROOM-32/ESP32 Dev Module, не S2/S3/C3.

## Сеть

Сохранены исходные сетевые параметры Config.h. При необходимости замените DEFAULT_WIFI_SSID/PASS и AP_FALLBACK_PASS
до сборки: публичные/встроенные пароли не являются индивидуальным секретом устройства.
Резервная AP ClimateCamera-AP, пароль 12345678, адрес 192.168.4.1.
Web UI: http://<IP>/; OTA: /update; API: /api/telemetry; mDNS: http://climate-camera.local.
OTA/API унаследованы без аутентификации. Используйте только доверенную локальную сеть,
не открывайте порт устройства в Интернет; для эксплуатации добавьте аутентификацию/сетевую изоляцию.
Появились поля dry_temp, wet_temp, sensor_type, sensor_error, fw_version, pressure_hpa.
При ошибке числовые измерения передаются null и интерфейс показывает --, а не старые значения.
Исходные уставки сохранены в NVS; температурная и RH-поправки старого SHT/HTU сбрасываются один раз при переходе на пару.

## Проверки

В BUILD_REPORT.txt — фактический результат сборки и тестов. Хост-тесты: python tests/run_tests.py (нужен g++).
Они проверяют формулу, диапазоны, CRC, запрет паразитного питания, независимые роли,
период конверсии, повторное обнаружение и переполнение millis.
Эмуляция не проверяет электрические параметры реального 1-Wire и психрометрическую точность.
Испытаний на физической ESP32, конкретных зондах, реле и холодильнике не выполнялось.
Первый запуск и проверку аварий проводите с отключёнными силовыми нагрузками.
